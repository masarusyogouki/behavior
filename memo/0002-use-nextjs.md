# Web アプリケーションに Next.js を採用する

- ステータス: 採用
- 対象: Web UI と API
- 関連: [0001-use-typescript.md](0001-use-typescript.md)

## 背景

プロジェクト全体を TypeScript で実装する方針にしたことで、Web UI だけでなく API も TypeScript で作ることになった。

そこで、Web アプリケーションの構成として Vite、Next.js、Hono を候補に挙げた。

## 検討した選択肢

### Vite

Vite はフロントエンドの開発環境とビルドには適しているが、単体では API を含むフルスタックのアプリケーションフレームワークではない。SPA と API を別々に構成することになるため、UI と API の両方を作る今回の要件には積極的に採用する理由が弱いと判断した。

### Hono

Hono は TypeScript で API を実装する候補になる。ただし、これまで利用した経験がなく、採用時にはフレームワークの学習と設計の検証が必要になる。また、UI については別の構成を組み合わせる必要がある。

### Next.js

Next.js では、React を使った UI と TypeScript の API を同じフレームワーク内で実装できる。UI と API の構成を分けずに開始できるため、初期段階の技術構成を単純に保ちやすい。

また、これまでに多少利用した経験があり、未知のフレームワークを採用する場合と比べて、実装を始めるための学習や検証を少なくできる。

## 判断

Web アプリケーションには Next.js を採用する。

主な理由は、UI と API を TypeScript でまとめて実装できることと、過去の利用経験を活かして開発を始められることである。

## 見直す条件

次のような状況になった場合は、構成を改めて検討する。

- UI と API を独立して開発、配置する必要が生じた場合
- Next.js の機能が要件に対して過剰になり、構成や運用の負担が明確になった場合
- Hono などを採用することで得られる具体的な利点が、移行や学習のコストを上回る場合
