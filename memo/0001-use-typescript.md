# TypeScript に統一する

- ステータス: 採用
- 対象: フロントエンド、バックエンド、Playwright の実行部分

## 背景

当初は、フロントエンドに TypeScript、バックエンドに Go を採用する構成を検討していた。

しかし、このプロジェクトの中核となるブラウザ操作には Playwright を利用する一方、Playwright は Go 向けの公式 API を提供していない。

## 検討した選択肢

### TypeScript と Go を併用する

Go から Playwright を操作するには、次のいずれかが必要になる。

- Playwright と通信するための処理を自前で実装する
- コミュニティ実装である `playwright-go` に依存する

自前で実装した場合、Playwright のバージョンアップによって内部仕様が変わるたびに、追従してコードを修正する必要がある。この保守負担を継続的に引き受けるのは避けたい。

`playwright-go` を利用する場合も、そのメンテナンスが将来にわたって継続される保証はない。更新が止まれば、Playwright の新しいバージョンへの追従を最終的に自分たちで担うことになる。

### TypeScript に統一する

TypeScript では Playwright の公式 API を直接利用できる。Playwright の更新に合わせた対応を公式実装に任せられるため、独自の接続処理や非公式ライブラリを保守する必要がない。

## 判断

プロジェクト全体を TypeScript で実装する。

Go を採用した場合の性能や言語上の利点よりも、プロジェクトの中核である Playwright を公式にサポートされた方法で利用できることと、将来の保守負担を抑えられることを優先する。

## 見直す条件

次のような状況になった場合は、Go の採用を改めて検討する。

- Playwright が Go 向けの公式 API を提供した場合
- Playwright に依存しない独立した処理が増え、Go を採用する明確な利点が生まれた場合
